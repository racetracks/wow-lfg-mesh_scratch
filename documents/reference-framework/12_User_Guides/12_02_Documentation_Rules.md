## 1. Requirements for every interaction with the AI
These apply to every prompt, reply and output in every session, whatever the task; they are requirements of working with the AI, not only documentation rules.
- <a id="dec-00001"></a>`DEC-00001` **Every session output is recorded in the session's temp root:** every file, summary, answer or other output of a T2 or T3 task is written to its temp root ([`DEC-00004`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00004)) as an `<output>/` subfolder with its own `README.md`, the prompt in `prompts/NN.md`, links in the root `README.md`; the session's reply only links it. An output kept anywhere else (the session, the addon repo, a loose scratch folder) is not recorded. A deliverable that belongs elsewhere (a test zip, approved documentation) is hosted there as well and linked from the output's `README.md`.
- <a id="dec-00002"></a>`DEC-00002` **Anything referenced always has a link (critical):** every reference to something the reader may open (a file, folder, section, line, key, issue, PR, commit, release, build, zip, save, repo, page, or the file a named function, event, command or saved field lives in) in anything written for the author, in any session, repository or tool (replies, summaries, documents, drafts, temp READMEs, changelogs, issues and comments, PR bodies and review replies, commit message bodies, test and in-game check lists, agent and workflow reports) is a markdown link, never a bare path, number or name: scratch files `https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/<path>` (a section `#<anchor>`, a line `?plain=1#L<n>`), folders `tree/main/<path>`, downloads `raw/main/<path>`; addon repo files `https://github.com/racetracks/wow-lfg-mesh/blob/<branch>/<path>`; issues, PRs, commits and releases by their GitHub URL; keys by [`DEC-00023`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00023). The link text stays the short name. Not linked: commands and code in code blocks, and code names whose file is linked in the same sentence. Something that cannot be linked yet (an unpushed commit) says so beside its name. A reference found without its link is fixed in the same commit.
- <a id="dec-00003"></a>`DEC-00003` **Interaction requirements:** the rules of this section and of section 4 are requirements of interacting with the AI in every session and every task.
- <a id="dec-00004"></a>`DEC-00004` **The session's temp root:** `temp/<YYYY>/<MM>/<DD>/<hh-mm-ss>-<Ddd>-<name>/`: the UTC date and time of the session's first prompt, `<Ddd>` the English three-letter day of that UTC date (`LC_ALL=C date -u +%Y/%m/%d/%H-%M-%S-%a` gives `2026/11/23/06-11-56-Mon`), `<name>` the session's development branch without `claude/` (no such branch: the session id's last part), kept for the whole session (find it with `temp/*/*/*/*-<name>/`). It goes in every references file the session changes ([`DEC-00027`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00027)); its `prompts/NN.md` is the Context of every changelog row the session writes.
- <a id="dec-00005"></a>`DEC-00005` **Fetch fresh repos first, in every session:** before reading anything, `git fetch origin main` (and the session branch) in the addon repo and `git pull origin main` here, then `refkey.py check` ([`DEC-00037`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00037)); pull once per session; never work from a stale checkout. A push that is refused is pulled and retried.
- <a id="dec-00006"></a>`DEC-00006` **Next-session handoff:** every session temp root holds `.next/NEXT.md`, its latest handoff, overwritten at every delivery that commits and copied over the root `.next/NEXT.md` in the same commit; the addon repo's SessionStart hook prints it and the other sessions' handoffs of the last 24 h; the author's prompt wins. Format, sections and the 60-line cap: `.next/README.md#format`; `check_context.py` in the addon repo fails a missing or misshapen one. A session that only answers writes nothing.
- <a id="dec-00007"></a>`DEC-00007` **One home:** every documentation rule lives in this file only; `CLAUDE.md` files and other documents say when to read it and quote its keys, never a copy of its text.
- <a id="dec-00008"></a>`DEC-00008` **Startup files cite keys and paths bare:** the files a `CLAUDE.md` loads at session start are written for the AI: keys resolve through `16_Registries/REGISTRY.md` (key, owner, file, title; the anchor is the key in lower case), and a `scratch:` path is in this repo. `link_keys.py --startup` fails an inline link in them; the linked copy the author reads (`CLAUDE.linked.md` here, `docs/linked/CLAUDE.linked.md` in the addon repo) is generated with `link_keys.py --render` whenever its source changes.
- <a id="dec-00009"></a>`DEC-00009` **Agent-ready output:** every document is shaped for the cheapest agent that reads it next: a header line first (purpose · owner · status · related), stable `##`/`###` anchors so a reader takes one section, each section self-contained and inside the caps of the addon repo's `.claude/agents/consultant.md#context-caps`, tables and pointers before prose, current truth only (history in the Changelog).
- <a id="dec-00010"></a>`DEC-00010` **Context caps and docs with code:** code is never capped, but every code change updates its documentation in the same delivery (the code map, the feature's documents, the build history's `Docs updated:` line), pointing to the code by `path:line`; the addon repo's `check_context.py` checks the caps, the startup size and this rule.

## 2. Mandatory Documentation Requirements
**No exceptions** other than [`DEC-00011`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00011), and none without the author's OK.
- <a id="dec-00011"></a>`DEC-00011` **The one exception (`temp/`):** all temporary workspace memory goes in `temp/<YYYY>/<MM>/<DD>/<hh-mm-ss>-<Ddd>-<workspacename>/` (a subfolder per thread when one workspace runs several threads). Its root holds a `README.md`, updated with the prompt strings and the references for context, and it is never deleted. `temp/` is excluded from every other rule in this section.
- <a id="dec-00012"></a>`DEC-00012` **Every major capability** (each addon folder, feature, sub-feature or project) has one documentation folder whose root holds all of: `00_Appendix.md`, `00_References.md`, `00_Decisions.md`, `00_Changelog.md`, `01_Summary.md`, `02_Requirements.md`, `03_Scope.md`, `04_High_Level_Design.md`, `05_Detailed_Design.md`, `06_Architecture.md`, `07_Roadmap.md`, `08_Operations.md`, `09_Current_Features.md`, `10_Planned_Features.md`, `11_Known_Issues.md`, `12_User_Guides.md`, `13_Release_Notes.md`, `14_Code_Reference.md`, `15_Tests.md`, `16_Registries.md`, `claude.local.md`, `Readme.md`; and for each of `08_Operations` to `16_Registries` a subfolder `NN_<Name>/` with `Readme.md`, `claude.local.md`, `NN_00_Appendix.md`, `NN_00_References.md`, `NN_00_Changelog.md`, `NN_01_Summary.md`.
- <a id="dec-00013"></a>`DEC-00013` **Every time documentation is constructed, create the whole root set** (never one file at a time), with keys from the registry (`refkey.py alloc`), pushed before use.
- <a id="dec-00014"></a>`DEC-00014` **Documents are documents, not databases:** no transactional data (counters, ledgers, logs, running tables of builds or measurements) in a document. Registries live only in a folder's `16_Registries/` (indexed by `16_Registries.md`); other documents link them. Tests (`TST`) and in-game checks (`CHK`) are defined in `15_Tests.md`, detail files in `15_Tests/`.
- <a id="dec-00015"></a>`DEC-00015` **Locations:** approved documentation goes in `documents/` (layout [`DEC-00017`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00017)); every draft sits in its own folder `drafts/<group>/<name>-<YYYY-MM-DD>-draftN/` with the same root set, and its `Readme.md` lists which `temp/` workspace `README.md` files may be cited for future context.
- <a id="dec-00016"></a>`DEC-00016` **Every folder and subfolder carries its own `claude.local.md`** with these rules and an "Excluded files" list of the files in that folder with no relevant content: (1) keep a document with no information extremely brief, telling the reader that the appendix, summary and references say where to find what they want; (2) **when reading or reviewing documentation, never open, read, crawl or index a file it excludes**; (3) **when updating documentation, never update a file it excludes**; (4) add every document with no relevant content to the list, and take a file off only when content for it arrives (filled in the same commit). Never excluded: `Readme.md`, `claude.local.md`, every changelog, the root `00_Appendix.md`, `00_References.md`, `00_Decisions.md`, `01_Summary.md`, and everything in `13_Release_Notes` and `14_Code_Reference`. Written by `write_claude_local.sh`.
- <a id="dec-00017"></a>`DEC-00017` **Layout:** `documents/addons/<addon folder>/`, `documents/features/<feature>/`, `documents/sub-features/<sub-feature>/`, project-wide folders (`reference-framework/`, later `code-map/`) at the `documents/` root. A folder not yet documented holds only `Readme.md`, `claude.local.md` and `00_Changelog.md` (`placeholder_folders.sh`).
- <a id="dec-00018"></a>`DEC-00018` **Scripts:** every script built for a capability (to build its structure or maintain its documents) is stored in its `08_Operations/<purpose>/`, a subfolder named for what the scripts do, with a `Readme.md` row per script and a `claude.local.md`.
- <a id="dec-00019"></a>`DEC-00019` **The reference framework lives in `documents/reference-framework/`:** the registry `16_Registries/REGISTRY.md`, the tools `08_Operations/registry-tool/refkey.py` and `link_keys.py`; every location reference is listed in `16_Registries/16_02_Registry_Locations.md` (`registry_locations.sh`).
- <a id="dec-00020"></a>`DEC-00020` **Changelog in every document:** history goes in a `## Changelog` section at the end of each document, and every folder has its `00_Changelog.md` (`NN_00_Changelog.md` in a numbered subfolder). Every change adds a row (date, document or reference, change, reason, context); a retirement row names the retired reference, its replacement and the reason.
- <a id="dec-00021"></a>`DEC-00021` **`claude.local.md` rules 5 to 7:** (5) the changelog rule ([`DEC-00020`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00020)); (6) **cite context:** when drafting or changing a reference, cite the temp workspace memory it came from (a `prompts/` entry or output `README.md`) or its stakeholder input (`STK`) key; (7) in a draft only, a **Promotion watch** table of every change that must carry over to live, emptied at promotion.
- <a id="dec-00022"></a>`DEC-00022` **Prompt log:** every prompt the author gives a workspace is logged in `temp/.../prompts/NN.md` (input verbatim, output, links) with a row in `prompts/README.md` (the addon repo's `log-prompt.py` hook writes it in agent sessions). Documentation summarizes the entries as stakeholder inputs (`STK`, proposed type, written `STK-pNN`) in `02_Requirements.md` section 1.
- <a id="dec-00023"></a>`DEC-00023` **Linked keys (critical):** every quoted key in every document (documents, drafts, temp READMEs, changelogs) is a link to its definition: its anchor, else its definition line (`blob/main/<file>?plain=1#L<n>`), else its issue, folder or registry line. Run `python3 documents/reference-framework/08_Operations/registry-tool/link_keys.py <folder or file>` on everything a delivery writes, before the check; `--check` must report 0 unresolved.
- <a id="dec-00024"></a>`DEC-00024` **Decisions document (critical):** every documentation folder has `00_Decisions.md` (never excluded): 1 Waiting on the author (key, what is needed, where it is explained, what it blocks), 2 Open decisions (key, question, options, recommended, built on meanwhile, context), 3 Decisions made (newest first: key, decision, answer, date, source, context). Every decision asked, answered or changed is recorded there and in the temp README tables in the same commit.
- <a id="dec-00025"></a>`DEC-00025` **Current temp READMEs with decisions:** every output `README.md` in the session's temp workspace (the root `README.md` is an index) is refreshed to the latest state at each delivery; before Recent prompts each has `## Decisions for you` (`| Key | Question | Options | Recommended | Built on meanwhile |`, then an "Also waiting on you (not decisions):" line) and `## Decisions made (this session's context)` (`| Key | Decision | Date | Source |`, newest first); an empty section says "None".
- <a id="dec-00026"></a>`DEC-00026` **Changelog before link:** every changelog row's Context ends with `before [<sha7>](https://github.com/<owner>/<repo>/blob/<sha>/<path>)` for each changed document, its last commit taken before committing (`sh documents/reference-framework/08_Operations/structure-builder/before_link.sh <path>`, run in the repo holding it), or `before: new`.
- <a id="dec-00027"></a>`DEC-00027` **Session context in references:** every `00_References.md` and `NN_00_References.md` has a Session context section linking the temp root of each session that wrote or changed that folder, one row per workspace (date, link, what it wrote), added in the same commit, **always the current session's own, every time** (`build_root_set.sh` writes it when `TEMP_WS` is set).
- <a id="dec-00028"></a>`DEC-00028` **Header block:** every document opens with its purpose, owning component, last updated (session reference), status and links to related documents (the one-line form of [`DEC-00009`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00009) satisfies it).
- <a id="dec-00029"></a>`DEC-00029` **Drafts, documents and history share one layout:** `drafts/` mirrors `documents/` (`addons/`, `features/`, `sub-features/`; project-wide drafts at its root); retired documentation lives in `history/<addon|feature|sub-feature|project>/YYYY-MM-DD-<folder>/`. Release hosting (`releases/`, `latest/`, docs zips) is separate.
- <a id="dec-00030"></a>`DEC-00030` **Retire to history:** documentation retired from `documents/`, and a draft once promoted, moves to `history/` (`git mv`) with pointer stubs left at the old path (`leave_pointers.sh`); the promoted document's `00_References.md` names it in its History section, with a changelog row. `promote_draft.sh`, `start_revision_draft.sh` and `move_files.py` do the moves and repoint live links (never `history/`, `temp/`, changelogs or commit-pinned links).
- <a id="dec-00031"></a>`DEC-00031` **Key anchors:** every key definition starts with `<a id="<key in lower case>"></a>`; every appendix links each key to `file#key`.
- <a id="dec-00032"></a>`DEC-00032` **How documentation work is run:** (1) start fresh ([`DEC-00005`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00005)), `git status` both repos, adopt or remove leftovers of an interrupted run and log them; (2) log the prompt verbatim ([`DEC-00022`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00022)); (3) list and allocate every key in one batch (`alloc_keys.sh`), push the registry, then write; never a guessed key; a duplicate allocation keeps the first and retires the later; (4) build structure with the scripts ([`DEC-00034`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00034)), updated first; test a script that moves or writes many files on a full copy (`cp -a`, `pwd` checked), never the real checkout; (5) write with keys, anchors, `STK` sources and changelog rows; an unanswered decision is built on the recommendation and says so; (6) list draft revisions in its `13_Release_Notes.md`; (7) `link_keys.py`, `refkey.py check`, one commit per delivery; no PR here; (8) answer in a temp output `README.md` ([`DEC-00025`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00025), [`DEC-00045`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00045)); (9) reply in a few lines with links; (10) an issue is created first, its `ISS` key allocated with the GitHub number in the title, then its body written.
- <a id="dec-00033"></a>`DEC-00033` **Credit other developers:** code, logic or media learned from or used from another developer is credited by name, licence and link in `00_References.md` (Credits) and in the release notes of every release that ships it (`history.txt` and `docs/latest/release-notes/<version>.md`).
- <a id="dec-00034"></a>`DEC-00034` **Build structure with the scripts:** update the scripts in `08_Operations/structure-builder/` first, then run them (`build_root_set.sh [--draft]`, `build_documents_tree.sh`); never write a root set by hand.
- <a id="dec-00035"></a>`DEC-00035` **Every numbered item a document defines has a framework key of its type;** a kind of item with no type waits for a new type (the author's OK) and is written `TYPE-pNN` until then. Never a bare numbered series (`N1`, `G3`). Agent reports use the session reference IDs of the addon repo's agent pack.

## 3. Reference framework
No exceptions without the author's OK.
- <a id="dec-00036"></a>`DEC-00036` **Keys are `<TYPE>-<NNNNN>`:** a 3-letter type, 5 digits from `00001`, one counter per type, project wide; never reused, renumbered, guessed or typed by hand. Types: `CMP` component, `ARC` architecture, `HLD` high level design, `DDS` detailed design, `IMP` implementation plan, `STP` implementation step, `ISS` issue, `APX` appendix, `SAV` SavedVariables decision, `DEC` decision, `TST` test, `CHK` in-game check, `BLD` build record, `RET` retirement. A new type needs the author's OK. A place inside a document is `KEY:section`.
- <a id="dec-00037"></a>`DEC-00037` **The registry is the only source of the next integer:** allocate with `python3 documents/reference-framework/08_Operations/registry-tool/refkey.py alloc <TYPE> <CMP-key> <file> "<title>"` (several: `alloc_keys.sh`) on a freshly pulled `main`, and push the registry before the key is used anywhere. `refkey.py check` must report 0 problems before every docs commit, and is run after every pull: a problem anyone left is fixed in the next commit with a changelog row ("found by the check on pull") and named in the temp output. Commits are never blocked; nothing runs on GitHub.
- <a id="dec-00038"></a>`DEC-00038` **Every documentation folder carries `00_Appendix.md` (its keys, each linked to `file#key`) and `00_References.md`** (retirements, mappings, credits, history, session context; empty tables until the first), created with the folder's first document.
- <a id="dec-00039"></a>`DEC-00039` **Retire, never delete (`RET`):** when an item is replaced, merged, split or dropped, allocate the replacement first, then `refkey.py retire <OLD> <NEW|-> <CMP-key> <folder>/00_References.md "<reason>"` (next `RET`, old ledger row marked "(retired, RET-n)", mapping row in the registry); push the registry, copy the row into that folder's `00_References.md`, mark the old definition "(retired, RET-n)" (keep its text), add both keys to `00_Appendix.md` and point live documents at the new key.
- <a id="dec-00040"></a>`DEC-00040` **A summary is a document:** asking for a summary (status, session, project, review or release, wherever kept) is asking for a document; every rule of sections 2 and 3 applies to it.
- <a id="dec-00041"></a>`DEC-00041` **Summaries end with a references table:** every summary (a temp output `README.md`, a `summary/` file, any status, session, project, review or release summary) ends with `## References`, one table `| Reference | Title | Link |`, one row per thing it references, each a full markdown link; it is the last section, after the prompt table ([`DEC-00045`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00045)), with the reference-style link definitions below it.
- <a id="dec-00042"></a>`DEC-00042` **Table of contents in every summary, report and document:** a `## Contents` section right after the heading and opening line, listing every `##` section (and `###` where there are several), each linked to its anchor. A file with no sections (a brief excluded document, a `claude.local.md`) needs none.
- <a id="dec-00043"></a>`DEC-00043` **Graphs in every summary and report:** data is supported with Mermaid charts GitHub renders (`pie` shares, `xychart-beta` bars and trends, `flowchart` plans and flows, `gantt` schedules, `quadrantChart` priorities) and heat maps as tables of shaded cells with a legend; the numbers stay beside each chart in a table; no chart where there is no data.
- <a id="dec-00044"></a>`DEC-00044` **A key is defined once** (its row or heading starts with it, [`DEC-00031`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00031)) and quoted everywhere else. PRs, commits, issues, history and code comments quote keys, never allocate them; **the addon repo never holds a registry.**

## 4. Records, links and summaries
- <a id="dec-00045"></a>`DEC-00045` **Each T2 or T3 output has its own subfolder** `temp/.../<output>/README.md` (what it is, the summary, the reference links); memory holds only that folder's link, never the content. Every temp output `README.md` ends with a table of the recent prompts, answers and outputs (`| # | Prompt | Answer | Output |`), links reference-style and collected at the bottom, then the references table ([`DEC-00041`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00041)).
- <a id="dec-00046"></a>`DEC-00046` **A project status summary for every PR:** every session that hands over an addon repo PR writes one `summary/<project>-<YYYY-MM-DD-hh-mm>.md` in the same delivery: last release, last merged build, the PR handed over and its state, the next step, what waits on the author, drift found, then Contents, graphs and the references table. The next session records the merge in its own file. The newest file is named in the `readme.md` index.

## 5. Naming conventions
- <a id="dec-00047"></a>`DEC-00047` **Naming conventions:** plain words, dates `YYYY-MM-DD` (with time `YYYY-MM-DD-hh-mm`, UTC), versions in file names, the user is "the author" (never a name or gendered pronoun). Every name follows this table:

| Thing | Form | Example |
| --- | --- | --- |
| Key | `<TYPE>-<NNNNN>`; proposed `TYPE-pNN`; a place `KEY:section`; anchor `<a id="<key lower case>">` | [`DEC-00047`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00047), [`DEC-00012:2`](https://github.com/racetracks/wow-lfg-mesh_scratch/blob/main/documents/reference-framework/12_User_Guides/12_02_Documentation_Rules.md#dec-00012) |
| Root set file | `NN_Name.md`, words joined by `_`, each capitalised | `04_High_Level_Design.md` |
| Root set subfolder file | `NN_00_Appendix.md`, `NN_00_References.md`, `NN_00_Changelog.md`, `NN_01_Summary.md`; detail files from `NN_02_<Title>.md` | `12_02_Documentation_Rules.md` |
| Folder readme | `Readme.md` inside `documents/`, `drafts/`, `history/`; `README.md` in scratch top folders, `temp/` and outputs | |
| Addon documentation folder | the addon folder name exactly | `documents/addons/<AddonFolder>/` |
| Feature, sub-feature | lower case, hyphenated, ending `-helper` | `documents/features/search-helper/` |
| Project-wide folder | lower case, hyphenated, at `documents/` root | `documents/reference-framework/` |
| Script folder | `08_Operations/<what-it-does>/`, lower case, hyphenated | `08_Operations/structure-builder/` |
